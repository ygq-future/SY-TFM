# Vault 启动即时同步设计

## 背景

应用启动后会立即读取本地 Vault 状态，但现有远端同步只由定时器触发。`setInterval` 不会在注册时执行回调，因此默认刷新间隔为 30 秒时，第一次远端检查也会延后约 30 秒。

## 目标行为

- 应用启动且 Vault 本地状态首次读取完成后，如果同步已启用，立即发起一次非阻塞的远端协调。
- 如果 Vault 未配置或已暂停，不发起远端请求。
- 启动协调只触发一次；React StrictMode 的开发期重复 Effect 不得造成重复同步。
- 保留现有定时同步、设置关闭同步和进入后台前同步行为。
- 启动同步失败不弹出额外提示，不阻塞应用；继续沿用现有状态刷新和下一轮定时重试。

## 实现方案

在应用壳层增加一个 `useRef` 启动门闩。Effect 等待 `vaultStatus` 从 `null` 变为已读取状态，然后立即将门闩标记为已处理：

- `enabled === true`：异步调用现有 `reconcileVaultState()`。
- `enabled === false`：不调用远端同步，但仍关闭启动门闩，避免用户稍后手动启用时被误当成启动同步。

该 Effect 不等待同步完成，因此不延迟首屏渲染。它复用现有协调函数，不增加新的后端命令、协议分支、数据结构或平台判断。

## 验证范围

- 回归测试确认存在一次性门闩、首次状态未加载时等待、状态读取后先关闭门闩，并仅在启用时调用协调函数。
- 运行前端 lint、format、完整测试与生产构建。
- Android、Windows、macOS、Linux 和 iOS 共用同一应用生命周期逻辑；本次不修改平台专项 UI 或存储行为。
